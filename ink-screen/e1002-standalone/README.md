# E1002 独立版设计

一台可以送人的桌面月历和相框。ESP32 自己保存配网信息、显示日历、接收图片和管理相册。手机用浏览器操作，无需账号、专用 App 或常驻服务器。

打开 [交互稿](design/index.html) 可以模拟配网、按键、上传照片和服务休眠。稿件默认展示日历，点「模拟恢复出厂」可以体验首次配网。二维码是演示用的，页面不会发起联网请求；选中的照片仅在当前页面预览。

**当前为浏览器交互稿，独立版固件尚未编写。** 已安装 Pixel 固件的设备可以先看静态样张，操作见 [烧录与实机预览](烧录与实机预览.md)。

## 设备画面

- 日历采用 800 × 480 横向布局。左侧显示今天的公历、星期、农历和六色山水。右侧以周一为首列排列月历，补齐首尾周的跨月日期，蓝底标记今天。初一显示月名，闰月标「闰」，常见节日按公历或农历计算。
- 图片铺满屏幕。取景框固定为 5:3，默认居中，可以缩放并水平、垂直移位。左下角白底扫码区也在取景预览中标出，便于避开人物脸部等主体。两种模式均使用黑、白、红、黄、绿、蓝六色，交互稿色值用于预览，实机色彩以打样为准。
- 两种模式的左下角都只显示带白底静区的二维码，上传操作见开箱说明。二维码指向上一次有效的局域网地址，服务到期后保留画面。再次唤醒时若 IP 未变，可以直接使用屏上二维码；若变了则刷新二维码。

## 固件计划支持的开箱和上传流程

1. 首次开机或恢复出厂后，E1002 建立临时配网热点，屏上显示带热点名和随机密码的入网二维码。手机扫码加入热点，在配网页选择家里的 2.4 GHz Wi-Fi 并输入密码。若系统未自动弹出配网页，手动打开屏上提示的 `http://192.168.4.1`。
2. ESP32 在保留配网页的同时尝试连接家庭 Wi-Fi。连上并取到 IP 后保存配置，默认进入当天所在月的日历，同时开启首次上传窗口。连接失败时显示错误并允许重试。配网热点空闲也可超时休眠，长按刷新键重开。
3. 后续传图时，长按绿色刷新键约 1.5 秒。ESP32 连上已保存的 Wi-Fi，启动 `8080` 端口上的上传服务。手机连到可与设备互通的局域网，再扫码打开上传页。
4. 手机选择照片，在固定比例内调整取景。浏览器显示最终 800 × 480 六色效果和待传大小，用户确认后发送位图。保存成功后设备自动切换到图片模式。手机端区分「已保存」和「屏幕刷新中」，避免用户把全刷的等待当成上传失败。
5. 上传服务成功启动后开放 5 分钟。扫码打开上传页或提交上传等有效访问后，从该次访问开始重新计 5 分钟；活跃传输中不休眠。后台轮询、无效请求和浏览器自动加载的资源不计入续时。空闲到期后停止服务、关闭 Wi-Fi 并进入深睡，电子纸保留原画面。

如果保存的 Wi-Fi 已失效，连接尝试在约 20 秒后结束并显示重配提示。可同时长按前后键进入设备设置页，使用前后键选择重配网络或恢复出厂，再用刷新键确认。重配保留照片，恢复出厂会清除 Wi-Fi、相册、显示状态与上传凭据。

## 按键

| 按键 | 日历模式 | 图片模式 |
| --- | --- | --- |
| 刷新短按（GPIO3） | 切到上次查看的照片 | 切回月历 |
| 刷新长按约 1.5 秒（GPIO3） | 开启或续期上传服务，留在当前月 | 开启或续期上传服务，留在当前照片 |
| 后退（GPIO5） | 上一月 | 上一张 |
| 前进（GPIO4） | 下一月 | 下一张 |

三键都可唤醒设备。离线翻页和切换模式不主动打开 Wi-Fi。长按触发后，松手不再触发短按。空相册仍显示扫码区；交互稿中的色块风景用于展示图片模式。相册按上传顺序浏览，在首尾停止。

## 固件方案

- **显示和时钟**。沿用仓库现有工程的 E1002 六色屏驱动和按键映射。用固定尺寸字形在设备端画月历，处理跨年、闰年和六周月份。交互稿使用浏览器的中文农历，固件计划内置离线换算数据，并用历表验证月首和闰月。通过配网页设置本地时区，用手机时间初始化板载 RTC，联网时可用 NTP 校时。离线由 RTC 保持时间，仅在日历模式下定时跨日唤醒。日期未设置时，提示打开配网页校时。 [香港天文台公历与农历对照表](https://www.hko.gov.hk/tc/gts/time/conversion.htm)
- **Web 服务**。配网页仅在临时热点上提供。上传页随固件提供，手机端解码、裁切、缩放和转色，原始照片留在手机。裁切结果以 800 × 480 固定尺寸打包，每像素 4 位，未压缩为 192,000 字节（187.5 KiB）。优先发送更小的无损 DEFLATE 数据。遇到压不小或浏览器不支持编码时发送打包位图。设备解码上限为 192,000 字节，核对解码后长度、颜色索引和校验值。链接形如 `http://192.168.1.42:8080/#<设备上传码>`。上传码随机生成，恢复出厂时轮换。设备只在唤醒窗口内提供上传接口，每次上传都验证上传码。若路由器隔离无线客户端，手机需切换到允许与设备互通的网络。 [浏览器无损压缩规范](https://compression.spec.whatwg.org/)
- **相册**。为 LittleFS 计划预留至少 2.25 MiB，保存最近 8 张照片和一张写入中的临时文件。配网和状态放在 NVS。上传先写临时文件、校验并提交，再切到新画面并清退最旧的有效照片。断电重启后恢复最新有效索引，保留此前已提交的照片，清理未完成的写入。
- **刷新和休眠**。E1002 彩色全刷通常要十几到几十秒。上传、按键和续时与刷新分开处理，连续翻页合并到最终页。设备在休眠前保存当前模式和页码。画面没有变化时不全刷；关掉 Wi-Fi 后电子纸仍保留现有画面。

## 实机验收

- 用 Android 和 iPhone 各完成一次扫码配网，验证密码错误重试、手动入口和换路由器后的重配。
- 日历能正确跨年、显示闰年二月和六行月份，农历初一换月、闰月和年初准确，离线跨日后更新今天的标记。
- 两种模式都能通过长按开启上传。第 4 分钟扫码后再获得 5 分钟；到期后手机无法访问，屏幕仍保留原画面。验证 DHCP 地址变动时的新二维码，以及地址相同时无需重刷。
- 上传横图、竖图和透明 PNG，检查缩放和移动后的取景、二维码遮挡区和六色显示一致。比较压缩前后的位图并验证终端能正确解压。第 9 张后能离线浏览最新 8 张；传输中断或断电后旧照片仍能显示。
- 测量上传、全刷、深睡三种状态的耗电，验证三键唤醒和二维码在实体屏上的可扫性。
