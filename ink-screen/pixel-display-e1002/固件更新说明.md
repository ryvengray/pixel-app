## 1. 打开终端并进入固件目录

在连接 E1002 的 Mac 上执行：

```sh
cd /Users/ryven/Projects/pixel-app/ink-screen/pixel-display-e1002/firmware
```

PlatformIO 使用用户目录中的持久环境：

```sh
/Users/ryven/.platformio/penv/bin/pio --version
```

本说明使用完整路径，不依赖终端 PATH。该环境位于 `~/.platformio/penv`，不会因系统清理临时目录而丢失。也可以使用 VS Code 的 PlatformIO 终端，并将后续命令中的完整路径替换为 `pio`。

下载依赖需要代理时，在当前终端设置：

```sh
export https_proxy=http://127.0.0.1:7897
export http_proxy=http://127.0.0.1:7897
export all_proxy=socks5://127.0.0.1:7897
```

先确保本机代理软件正在运行。已有依赖通常无需重新下载。

## 2. 首次烧录前检查

检查 `include/config.h` 已填写 Wi-Fi 和令牌，服务器配置应为：

```cpp
#define API_BASE "http://192.168.0.160:18000"
#define MQTT_HOST "192.168.0.160"
#define MQTT_PORT 1883
#define DEVICE_ID "desk-01"
```

`API_TOKEN` 必须与 Ubuntu 上 `.env` 中的 `PIXEL_TOKEN` 相同。密码和令牌不要提交到 Git。设备保持稳定 USB 连接，关闭占用串口的监视器和其他刷机程序。

确认服务器在线：

```sh
curl --noproxy '*' http://192.168.0.160:18000/health
```

预期包含 `"ok":true`、`"mqtt_connected":true`。这里绕过代理，直接访问局域网服务器。

## 3. 编译

```sh
/Users/ryven/.platformio/penv/bin/pio run -e e1002
```

看到 `SUCCESS` 才继续。编译产物位于 `.pio/build/e1002/`。出现错误时保留日志，先修复第一条编译错误。

## 4. 烧录到 E1002

先列出串口：

```sh
/Users/ryven/.platformio/penv/bin/pio device list
```

本次识别的串口为 `/dev/cu.usbserial-1440`，重新插拔或换 USB 接口后可能变化。以实际列表为准：

```sh
/Users/ryven/.platformio/penv/bin/pio run -e e1002 -t upload --upload-port /dev/cu.usbserial-1440
```

此命令会先检查并按需编译，然后写入固件。烧录会替换设备现有程序；过程中不要拔线或断电。看到写入校验通过及最终 `SUCCESS`，才表示烧录成功。

若一直停在连接阶段，先检查串口路径及占用情况，再尝试按住 BOOT、接入 USB 后松开，重新查看串口并执行 upload。若烧录后停留在下载模式，松开 BOOT 后按一次 RESET，或重新连接供电让设备正常启动。

## 5. 查看运行日志并验证

```sh
/Users/ryven/.platformio/penv/bin/pio device monitor --port /dev/cu.usbserial-1440 --baud 115200
```

按 Ctrl+C 退出。若没有启动日志，可在监视器打开后按一次 RESET。当前配置启用了 USB CDC，运行日志所用串口可能与 USB 转串口不同；若没有输出，再次列出串口检查是否出现新端口。没有串口输出本身不能证明烧录失败。

按《操作手册》第 8 步提交一条新的测试消息，再查询 desired。应满足：

- `displayed_version` 等于当前 `version`，且 `status` 为 `displayed`。
- 肉眼确认屏幕文字、颜色和方向正确。

设备会保留上一次显示版本，相同内容可能不会再次刷新；验证更新时请换一条测试文字。刷新限速和轮询可能延迟更新，先等待约两分钟。

## 6. 修改代码后如何更新

每次修改 `src/main.cpp`、`include/config.h` 或 `platformio.ini` 后：

1. 保存文件，退出串口监视器。
2. 执行第 3 步编译，确认 `SUCCESS`。
3. 执行第 4 步 upload，确认 `SUCCESS`。
4. 按第 5 步检查运行及实际画面。

只修改电脑上的文件，设备不会自动更新。Wi-Fi、IP、令牌和设备 ID 都编译进固件。首次启用 OTA 仍需 USB 烧录一次；之后可在 Ubuntu 运行脚本指定版本号，一次完成编译与发布，在下次唤醒时无线更新，详见《OTA更新说明》。变更服务器地址或令牌时，需要保证设备仍能从旧地址与旧令牌完成新固件下载。

通常不必清理构建缓存。只有怀疑缓存或更换关键构建配置时，先执行：

```sh
/Users/ryven/.platformio/penv/bin/pio run -e e1002 -t clean
/Users/ryven/.platformio/penv/bin/pio run -e e1002
```

普通 upload 不主动擦除整个 Flash，固件使用的 NVS 显示版本通常会保留。不要为了常规更新执行整片擦除。

## 7. 哪些修改需要重新烧录

| 修改内容 | 应执行的操作 |
| --- | --- |
| 固件代码、Wi-Fi、服务器地址、设备令牌、设备 ID | 重新编译后 USB 烧录，或按 OTA 说明发布 |
| 仅通过 API 修改屏幕标题、正文和颜色 | 提交显示请求即可 |
| Ubuntu 的 server 代码、requirements 或 Dockerfile | 在 Ubuntu 项目目录执行 `docker compose up --build -d` |
| Ubuntu 的 `.env` 或 Compose 配置 | 执行 `docker compose up -d`；令牌或对外地址变化时也需同步更新固件 |
| 文档或 Python 调用示例 | 不需要烧录，使用更新后的文档或脚本 |

## 8. 保留可回退版本

升级前保留上一版源码、对应的本地配置及构建依赖版本。需要回退时，恢复对应源码和配置，重新编译并 upload。不要把只有一个 `firmware.bin` 的备份当作完整恢复方案；引导程序和分区配置也可能影响恢复。

固件文件包含编译进去的 Wi-Fi 密码和 API 令牌，源码配置与构建产物都应妥善保存，不要公开分享。
