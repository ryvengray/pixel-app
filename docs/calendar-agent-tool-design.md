# 日历 Agent 工具设计草案

状态：视觉方案已确认，首版源码已实现；构建与实际验收状态见 calendar-tools.md。日期：2026-10-23。

用户已确认深色星空、浅色山景的日历／记录抽屉／桌面大月历界面稿。所有用户可见文案统一使用“大姨妈”，包括页面、无障碍名称、提醒及 AI 回复；技术字段可继续使用 cycle／period，不将用词变更等同于功能已经实现。

## 1. 产品定位

一个“日历”工具，聚合重要日期、倒数／正数、大姨妈记录与预测。首页不新增入口卡片、状态徽标或常驻倒计时；从“功能与设置 → 工具 → 日历”进入，也能通过聊天打开。支持沿用工具抽屉／全屏两种展示方式。

Agent 是主要操作入口，日历页面负责浏览、手动修正和查看依据。所有 AI 与手动操作使用同一份数据、校验和提醒规则；不允许只生成“已记住”的回复而不实际保存。

参考：倒数日的重要日期、重复和提醒；美柚的大姨妈记录、月历着色与预测。保留本应用轻量、简洁的视觉，不引入资讯流、社区或额外首页模块。

## 2. 页面结构

顶部：返回、年月标题、女生轮廓图标、添加。

- 女生轮廓使用应用内矢量图标，正常显示时不配文字。选中为柔和强调底，未选中为轮廓；提供“显示／隐藏大姨妈内容”的无障碍名称和长按说明。
- 未配置时点击图标进入简短配置；配置后点击切换大姨妈图层，并记住选择。
- 隐藏图层后，同时隐藏月历着色、日程列表大姨妈条目、预测摘要和图例。它只控制展示；提醒与 AI 访问分别设置，不随隐藏动作自动关闭。
- 顶部可切换“月历／日期列表”。月历下方是选中日期的内容，未选中日期时显示近期重要日期。没有内容时显示简短空态。
- 月历工具没有独立大封面。使用现有主题的背景、字体与柔和表面。

月历示意：

    ‹       2026年10月        [女生图标] [+]
                 月历 · 日期列表
    一    二    三    四    五    六    日
                 月份网格
    今天 · 10月23日
    妈妈生日                         还有8天
    下次大姨妈                         预计还有3天

    近期
    结婚纪念日                       还有18天

示例内容仅用于说明布局，不是用户数据。

日期列表按下次发生时间排序；正数纪念日可置顶，显示“已经 X 天”，同时显示下次周年还有多久。过去的一次性事件默认归档，可查看。

月历格子以公历数字为主，下方显示小号农历；初一显示农历月份，传统节日可优先显示节名，完整农历保留在日期详情和无障碍说明中。应用和桌面大月历共用日期换算，并保留农历生日按农历重复。普通事件为小点。普通事件的小点与大姨妈底色并存；选中态用外框，今天用数字强调，不盖住原有标记。同一天多个事件显示最多两个点，完整内容放下面的列表。

## 3. 重要日期

支持生日、纪念日、截止日、自定义事件；类别只帮助默认规则，不限制用户表达。

字段：标题、原始日期、历法、公历／农历、是否闰月、重复方式、显示模式、提醒规则、备注、是否置顶。

- 原始日期与下次发生日期分开存储，保证“已在一起多少天”与“下次周年还有多久”都能回答。
- 第一版支持一次性、每年重复；正数模式支持起始日和可选里程碑，例如第 100／1000 天。每月或自定义复杂重复可后续加。
- 农历生日按农历重复，不是每年复制同一个公历月日。保留原始农历及闰月信息；超出历法库支持范围明确提示。
- 只有月日的生日不推断出生年或年龄；需要计算年龄时再补充出生年。
- 2月29日的非闰年规则可选2月28日或3月1日；缺失的农历日期／闰月需要显式规则，创建时展示规则摘要，不静默猜测。
- 倒计时按所选时区的日历日期计算，当天显示“就是今天”，不按毫秒除以24小时计算。
- 对“已过多少天”默认起始日为第0天；“第几天”默认起始日为第1天，AI 回复明确采用的口径。

默认提醒建议：提前1天、09:00；可选择提前7／3／1天、当天或自定义。创建页面展示默认值；聊天未指定时间时使用用户已设置的默认值，并在保存结果中说明。

例：“记一下妈妈农历八月十五生日，每年提前三天提醒我。”保存后回复日期、重复和提醒摘要，提供“查看／撤销”。

## 4. 大姨妈功能

第一版一个跟踪对象，可填写称呼（自己、伴侣或自定义）；不强行根据账号性别判断功能是否可用。数据模型保留 profile_id，便于未来扩展，首版不做复杂多人切换。

初次配置只需：最近一次开始日期、通常周期长度、通常大姨妈天数、是否提醒。周期是两次开始之间的间隔；大姨妈天数是本次持续时间，表单分开解释。周期不清楚时允许先只记事实，不自动填28天并当作已知配置。

日常操作：

- “今天来了”：新增本次开始日期，状态为进行中，取消旧预测的到来提醒。
- “昨天结束了”：补充本次结束日期；没有正在进行的记录时，询问对应记录。
- “上次其实是10月3日”：精确定位对应记录后修正，重新计算未来预测。
- 可以补记历史、症状和备注；症状是可选项，不让记录变成问卷。
- 没有实际结束记录时，不因默认大姨妈天数到期就把本次标记为已结束。

### 4.1 配色和标记

| 内容 | 月历 | 列表 |
|---|---|---|
| 已记录大姨妈 | 柔和玫瑰色实底／连续圆角色带 | 实色小圆点、“大姨妈第 N 天” |
| 预计大姨妈 | 同色浅底加虚线边 | 空心点、“预计大姨妈” |
| 预计易孕窗口 | 淡紫色浅底 | 淡紫标记、“预计易孕期” |
| 预计排卵日 | 紫色小花或环形符号 | “预计排卵日” |
| 其他日期 | 默认背景；不加醒目的绿色安全标记 | 无大姨妈事项时不生成多余列表行 |

深浅色主题分别调色，不能只靠颜色区分；实线／虚线、图形和详情中的文字共同表达。实际大姨妈优先于预测大姨妈与预计排卵标记。

不把日历法推算出的普通日期称为“安全期”。即使周期规律，易孕窗口也会变化，界面不输出“绝对安全”或“不会怀孕”。预测详情中简短说明“仅为日期估算，不能作为避孕依据”。

### 4.2 预测原则

- 初始模式按用户配置的周期推算，下次开始 = 最近实际开始 + 周期长度；预测是派生数据，不写成真实大姨妈记录。
- 只显示近期预测（例如未来3个周期），越远越不应显示成确定日期；通知只安排最近一次预测。
- 积累至少3个完整周期间隔后，可建议启用“根据历史调整”；不擅自覆盖手动周期。自动模式使用最近若干完整间隔的稳健统计，并保留计算依据与算法版本。
- 不把持续较长或不规则的周期直接当作错误删除。缺失记录、跨度过大和明显不确定的输入需要用户修正／标记，历史数据保留。
- 记录波动明显时以预计日期范围和“波动较大”呈现，暂停精确到某一天的排卵标记；不伪造置信百分比。
- 排卵日期只能是基于周期的估算。具体推算公式和易孕窗口边界在实现前单独固定、写入算法版本，不能让 LLM 每次自由计算。
- 已经过了预计到来时间而没有记录时，提示“尚未记录本次开始”，不擅自判断已经来了、怀孕或存在疾病，也不持续滚动生成新的“实际大姨妈”。
- 支持暂停预测／提醒，例如暂时不跟踪；保留历史，不让所有生活阶段都套用普通周期规则。

默认大姨妈提醒建议：预计开始前2天09:00，单周期一次。录入实际开始后自动作废该预测的待发提醒。过期但尚未记录时，最多一个轻量记录询问，默认关闭重复催促。

## 5. 提醒与通知

日期提醒和大姨妈提醒共用调度基础设施，来源有区别。事件／周期事实为唯一依据，提醒只是派生任务。

- 事件修改、周期修正、删除、暂停后，先取消旧任务，再按新版本生成；已在推送队列里的旧任务也须作废。
- 幂等标识包含来源ID、发生日期、提醒偏移和规则版本；重复操作、服务重试或重新联网不重复通知。
- 采用事件／个人配置的 IANA 时区。明确“按所在地时间”还是“固定时区”；提醒时间用本地日期+时间+时区表达，再转换为调度时间。
- 日期级提醒无需闹钟级精确到秒。手机断网时本地提醒仍应可工作；服务器和手机不能同时各发一遍。
- 本机是首版日历提醒的唯一投递端，服务端现有普通提醒保留原职责。为新日历来源补手机调度、重启／时区／时间变化重排与通知权限处理，不能仅复用现有服务端定时器就声称支持离线。
- 系统限制导致未及时投递时，补发仍有用的提醒一次，过期很久则列入历史；界面明确通知未获授权的状态。
- 私密提醒在锁屏默认只显示“你有一条日历提醒”，进入应用后查看具体内容；是否显示详情可单独设置。
- 通知点击定位到对应日期／事件。AI 对话中的提醒基于同一任务ID标记已投递，避免通知和主动聊天分别提醒多遍。

## 6. AI 工具设计

所有动作都是结构化工具。自然语言解析由 Agent 完成，日期计算、规则校验、保存和预测由确定性逻辑完成。

| 工具 | 用途 |
|---|---|
| open_calendar | 打开日历，可定位日期、事件及切换大姨妈图层 |
| query_calendar | 查询日期区间、标题、类型、近期事项和倒数；返回可追溯ID |
| save_special_date | 新建／修改重要日期、重复和提醒规则 |
| delete_special_date | 按明确ID删除，可撤销 |
| get_cycle_summary | 查询指定日期范围的实际大姨妈、预测和计算依据 |
| save_cycle_record | 新建／修正开始、结束日期与可选备注 |
| delete_cycle_record | 删除明确记录并重新推算，可撤销 |
| update_cycle_settings | 修改周期、持续天数、预测模式、提醒和跟踪状态 |
| update_calendar_preferences | 修改图层显示和通知展示偏好 |

查询工具必须支持读到本地数据后继续同一轮推理，不是返回“打开工具页面”。大姨妈查询默认返回摘要；只有查询指定历史时才按需返回对应时间段。

对话示例：

- “这个月还有哪些值得记的日子？”→ 查询后按日期回答，不强行弹页面。
- “离我们的1000天还有多久？”→ 查到起始日期后使用日期计算结果。
- “把妈妈生日提醒改成提前一周。”→ 查找ID → 更新规则 → 回执说明。
- “最近一次是10月3日开始的，周期30天，提前两天提醒。”→ 保存事实和配置，返回预计下次日期及提醒规则。
- “我上次是什么时候来的？”→ 返回实际记录，不用预计日期回答。
- “这次预计什么时候来，为什么？”→ 返回估计范围、所用最近开始日期、配置／统计周期，以及不确定性。
- “日历里先别显示大姨妈。”→ 仅关闭显示；可在回执中简短说明提醒仍按原设置运行。

修改策略：

- 明确对象和日期的普通新增／修改直接执行，成功后简短回执和撤销，不每次弹确认。
- 同名对象或“上次”指代不清时先查询；仍歧义才问一句，不猜ID、出生年或月经事实。
- “最近不太舒服”不能自动记为大姨妈开始；“今天来了”等明确记录表达才写入。
- 删除全部、清空历史等批量破坏操作先展示具体范围再确认；单条可撤销删除不强迫多步操作。
- AI 不直接编辑预测日期；用户修正事实或规则，再重新生成预测。
- 修改返回 before／after、record_id、revision、operation_id、影响的提醒摘要和撤销标识。版本冲突时重新读取；重试同一 operation_id 不重复写入。
- 只有数据库事务提交成功后才能回复“已保存”；失败保留输入并说明未完成。预测或通知未建立时不能宣称“提醒已设置成功”。

## 7. 数据与接入

建议手机为事实数据的主存储，第一版手动和AI都操作手机上的同一日历库。服务端负责Agent编排，不保存第二份互相竞争的大姨妈事实。

建议实体：

- special_date：原始日期、历法、重复、显示模式、称呼／标题、备注、版本。
- reminder_rule：来源、提前天数、本地时间、时区、启停。
- cycle_profile：跟踪对象、手动周期／时长、预测模式、启停。
- cycle_record：实际开始、实际结束、进行中状态、备注、版本。
- calendar_preferences：大姨妈图层、提醒详情、AI访问选项。
- scheduled_occurrence：派生发生日期、来源版本、调度及投递状态。
- operation_log：幂等、修改前后和撤销；大姨妈记录不顺手复制到普通长期记忆或通用行为日志。

当前仓库已有客户端工具schema、固定动作白名单、服务端工具执行以及提醒／inbox。重要缺口：现有客户端动作主要是打开页面／保存生活记录，新增本地查询需要“服务端暂停工具调用 → 手机执行 → 上传所需结果 → 恢复同一轮Agent”的结果回传协议；手机直连LLM也必须复用同一个本地执行器。没有这条闭环，不能算AI真正能查询、修改日历。

接入点涉及 ClientTools／DecisionActions、本地执行器、AssistantApi／Agent checkpoint、server/app/client_assets/tools.json、server/app/main.py，以及快速路由注册。快速路由仅负责识别候选工具，不绕过参数／权限校验。需更新服务能力声明，旧版手机不收到未实现的工具。

大姨妈明细默认不加入普通聊天上下文、主动开场、Obsidian导出或通用同步。用户主动询问时，最小必要摘要会进入其配置的远程模型上下文，功能设置中明确说明；支持单独禁用AI访问，展示开关不替代访问设置。若以后增加云同步／导出，单独选择是否包含大姨妈数据。

## 8. 实现顺序建议

1. 先完成本地工具调用回传闭环、日期库、重要日期CRUD、月历／列表、重复／提醒及AI问询。
2. 再完成大姨妈事实记录、初次配置、开关图层、明确区分实际／预计的配色、近期预测和提醒。
3. 最后加入历史辅助调整、症状摘要、更复杂重复、选择性同步或导出。

以上是实施顺序，完整首轮范围仍包含重要日期和大姨妈核心能力，不将“大姨妈以后再说”当作本次设计目标。

## 9. 后续验收要点（尚未执行）

- 首页没有新增模块；设置入口和AI均可打开日历。
- 图标切换同时覆盖月历、列表、摘要和图例，重启后保留；不误改提醒。
- 实际／预计无需只靠颜色即可区分；同日普通事件不被遮住。
- 生日缺年份、农历／闰月、闰日、跨年、日期边界和时区切换行为确定。
- 新增、修正大姨妈事实后，预测和旧提醒同步作废重建；不会把预测当作事实。
- AI新增／查询／修改／撤销可闭环，失败不报成功，重复请求不重复写入。
- 未开启大姨妈AI访问时不会读取；普通导出、日志和锁屏不泄露明细。
- 离线、本机重启、通知权限未开启及恢复联网时的提醒状态可解释且不重复。

## 10. Android 桌面小组件（纳入首轮范围）

用户接受较大的桌面占用，因此优先设计完整的大月历，而不是把所有内容压进小格子。建议三个布局，共用日历事实和预测：

| 布局 | 建议尺寸 | 内容 |
|---|---|---|
| 大日历（首选） | 约4×4起，允许横纵拉大 | 年月、月历、女生图标、近期2—4条重要日期；开启大姨妈时包含预测摘要和相应标记 |
| 近期日期 | 约4×2起 | 今天日期、最近3条重要日期及倒数；可开启大姨妈摘要 |
| 单个纪念日 | 约2×2起 | 一个选定事件的大号倒数／正数和简短标题 |

尺寸是设计建议，不绑定Pixel桌面的某一种网格；实际布局根据启动器提供的宽高适配。尺寸较大时增加信息行和留白；尺寸较小时减少行数，保留可读字号和点击区域。

视觉延续首页：深色星空、浅色山景、柔和描边与玻璃质感、相同字体选项；背景透明度可调，允许用户选择更融入自己壁纸的低背景模式。桌面使用静态质感与少量固定光点，不运行首页的持续闪动和GL动画。玻璃感由半透明表面和纹理实现，不承诺模糊任意启动器壁纸。

交互：

- 左右小箭头翻月，点击年月回到本月；点击日期进入应用并定位当天。
- 点击具体事项进入对应详情；添加按钮进入记录抽屉。桌面不直接承载复杂输入。
- 大日历和近期日期组件保留女生轮廓图标，点击即可切换该组件的大姨妈显示。
- 每个组件单独保存所选事件、主题模式、透明度和大姨妈显示；不与应用内的图层开关强制联动，也不修改提醒开关。
- 初次添加时大姨妈显示默认关闭，配置中可主动开启；隐藏时同时去掉着色、图例和摘要，不留下可推断大姨妈的残余标记。
- 一个桌面可放多个实例，例如一个大月历和一个恋爱天数，各自独立。

更新：手动或AI修改保存后，更新受影响的全部组件；跨日、时区／系统时间变化、重启及主题变化时刷新日期和倒数。组件读取本地库，无需持续联网；调度受Android系统限制，回到应用／桌面交互时校正过期展示，避免以高频轮询维持动画。预测、颜色、日期计算均与应用共用，不另写一套规则。

Agent可以配置已有组件的内容（例如“桌面这张卡改成结婚纪念日”），需要以明确的组件ID定位，有多个匹配时才追问。向桌面新增组件通过系统固定流程让用户完成放置；不承诺AI能够绕过启动器授权自动摆放或任意调整位置。

后续验收包含：Pixel 9 Pro不同桌面网格、跨月6行月历、大字体、深浅主题、多个组件独立设置、隐藏大姨妈无残留、AI修改刷新和跨日更新。本轮仅补充设计，尚未实现或运行验收。
