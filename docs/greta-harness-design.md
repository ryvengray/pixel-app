# Greta 主动陪伴与首页输入设计

设计日期：2026-10-16。状态：实现进行中，用户要求暂停；接续以 [greta-harness-handoff.md](greta-harness-handoff.md) 为入口。验证情况见文末。本文中的时长、频率和尺寸是首版建议值，需要真机调整。

## 1. 体验目标

Greta 知道你交代过什么，能在合适的时机先开口；你进入首页就能回应她。首页保持现有玉绿色场景与角色主体，输入融入场景，只有录音时进入独立黑色界面。默认“说话”指文字表达，不自动播放声音。

三个基本原则：重要事情可靠到达；闲聊有上下文且有节制；用户正在输入时，主动内容让路。

首页就是持续对话的主场。用户与 Greta 各保留一个最新发言气泡，连续补充归为同一组；工具与内容有独立展示位。发送消息后留在首页，不切换到传统聊天列表。完整过程永久记录在历史中，首页替换气泡只改变展示，不删除消息。

## 2. 当前基础与缺口

- MainActivity 已有 PetScene、首页固定问候和点击角色进入 ChatPanel 的过渡；首页没有输入入口或主动消息状态。
- ChatPanel 已有文字输入、最近历史、本地记忆和回复请求，但发送逻辑与界面绑定，缺少共享草稿和可靠重试状态。
- server/app/main.py 已有模型工具循环、save_memory、create_reminder、15 秒检查一次的提醒任务、inbox 与 FCM。
- reminder 当前先标记 fired，再写入 inbox，进程在两者之间退出可能丢消息；推送失败不形成独立重试任务。
- Android 当前没有拉取 inbox 和阅读回执；通知点击没有携带消息 ID 定位到对应上下文。
- 目前没有录音权限声明、流式语音识别或录音手势状态机。

因此本次 harness 的范围包含事件、上下文、决策、工具执行、可靠投递及回执，而不只是更换提示词。

## 3. 主动开口的规则

| 类型 | 依据和触发 | 表达与渠道 | 收敛规则 |
| --- | --- | --- | --- |
| 明确提醒 | 用户交代的时间或已确认规则到期 | 首页提醒／后台系统通知；可完成、稍后、修改 | 不受闲聊配额影响；同事件去重 |
| 事项跟进 | 用户同意跟进的待办，到了约定窗口 | “昨天说的材料，今天还需要我提醒吗？” | 不凭记忆推断截止时间；已完成立即失效 |
| 首页续聊 | 首页真正进入前台，最近有未结束的话题 | “上次那个首页想法，要接着聊吗？” | 同话题每天最多一次，忽略后降低频率 |
| 轻量问候 | 当天尚无问候，间隔足够，且无更重要内容 | “回来啦，今天想先做点什么？” | 无合适内容可保持安静；不制造紧迫感 |

建议默认：普通主动开场每天最多两次、间隔至少四小时、一次前台会话最多一条；普通开场仅在首页出现，不发系统推送。23:00–08:00 不主动闲聊；用户明确指定这个时段的提醒仍按约定投递。设置可分别关闭“主动聊两句”和调整提醒通知。

“偶尔”由上下文、冷却与反馈决定，不采用每次打开随机抽一句话。第一版只使用已有聊天、明确记忆和提醒记录；定位、日历、其他 app 使用状态不是现成能力。

首页稳定停留约 1.2 秒后才允许显示候选消息。用户已点输入、正在录音、打开菜单或正在聊天时，不插入普通开场。到期提醒在这些状态下暂存，不盖住输入；恢复空闲后显示。

首页表现：角色轻轻回应一次；主动内容进入 Greta 当前气泡，遵循下文的独立替换规则。气泡不按时间自动消失；重新进入首页恢复两人各自最后一组发言。重要提醒同时有可操作事项卡，不因新气泡替换而丢失。可见内容和阅读状态分开记录，展示过不等于已完成。

普通开场直接在首页回应；点击气泡查看完整内容。有时限事项使用紧凑的“完成／稍后”操作。主动消息一经展示即进入同一聊天时间线，用户随后说“好”“晚点”时，携带来源消息 ID。多条事项时不擅自把“好”解释为全部完成。

### 3.1 两个独立的发言气泡

- Greta 气泡靠近角色，气泡尾部朝角色；用户气泡靠右、位于输入区上方。保持固定阅读位置，不按消息时间重新排序。
- 两个气泡槽位各自更新：用户新一轮发言只替换用户旧气泡；Greta 新一轮发言只替换 Greta 旧气泡。任何一方开口不会清除另一方。
- 用户发送后立即显示本地文本及发送状态；Greta 思考时保留她上次的话，用独立轻量状态提示。新回复首段可显示文字到达时，在原位替换旧气泡并逐步补全，避免生成失败留下空槽。
- “一句话”按一次连续表达理解，不按标点切分。同一人连续发送、对方尚未开始新发言时，合并为一个气泡中的多段文字；对方已开始新发言后，自己的下一条开启新组并替换旧组。分组以表达轮次为主，不用固定 3 秒将内容切断。
- 例：用户发送“明天提醒我”，紧接着发送“下午三点”“带上材料”，首页同一气泡按原序显示三段；历史仍保存三次原始发送、时间与 group_id。Greta 同一次回复中的多个流式片段与工具前后简短说明也归为同一回复组，不把 token 当成新消息。
- 合并展示与请求调度分开：建议首条提交后等约 800ms 的短暂补充窗口再请求回复；后续补充用新 revision 汇入当前轮次。生成期间收到补充时，尚未执行的旧计划暂停并重新评估，旧 revision 的迟到回复不得覆盖新回复。已经执行的工具保留真实结果并告知用户，不能因合并发言再次执行。
- 两个气泡默认各展示至多约 4 行；长文保留原文并提供“展开”，在底部详情层阅读。清单、文档等完整结果放内容区，气泡只说简短结论。窄屏或键盘出现时保持角色大小和位置、收起内容预览，优先保证当前气泡与输入可见。
- 连续发言的时间窗口是首版默认值，需用真实快速补充和语音场景校准；它不影响每次发送的独立持久化。

### 3.2 首页工具与内容区

在气泡区域与输入条之间预留一个按需出现的内容位，空闲时不占卡片空间。角色保持原位置和大小，气泡与内容位在周围自适应排布；键盘出现时允许遮挡下部场景，优先保持输入和气泡可读。

- 工具执行：显示自然语言状态，例如“正在创建提醒…”；完成后原位变为“明天 15:00 · 带上材料”，附修改、完成等实际可用操作。失败明确标记并提供重试。
- 内容展示：文档、列表、链接、打印结果等显示紧凑预览，点击展开底部详情层；返回仍是原来的首页与草稿。
- 多个任务：一个主卡位显示当前选中任务，上方用“进行中 2 · 查看全部”入口打开任务列表。新任务默认可选中，但用户正在查看某项时不抢走选择。
- 气泡替换不会删除任务卡。进行中、失败待处理、需要用户操作的事项持续可找到；已完成的普通结果可由用户收起，收起后保留轻量“最近结果”入口及历史记录。
- 只展示真实工具状态和产物，不展示内部推理或伪造进度百分比。工具事件关联调用 ID 与消息组，重试有幂等控制。

### 3.3 历史入口

首页右上角保留固定的“历史”入口，与设置菜单并列。打开独立历史页，按时间查看完整用户发言、Greta 回复、主动提醒、工具过程和结果；连续发送可视觉分组，但原始记录不被合并删除。首版支持日期分组、分页和跳到最新，搜索可随后补充。

点击任一首页气泡的“查看记录”可定位对应消息组。历史页默认用于阅读；选择“接着聊这条”后返回首页，并显示被引用内容，让后续回复带明确引用。普通返回首页不改变最新两个气泡，也不丢草稿。首页只是完整历史的最新状态投影，模型上下文不能只剩这两个可见气泡。

## 4. 首页底部输入条

静止态布局：

```text
          Greta             历史  ···

               角色场景

   ╭────────────────────────────╮
   │ 好，明天下午三点提醒你。   │  Greta
   ╰────────────────────────────╯

          ╭─────────────────────╮
       我 │ 明天下午三点提醒我   │
          │ 带上材料             │
          ╰─────────────────────╯

   [ 明天 15:00 · 带上材料  修改 ]

   ╭──────────────────────────────╮
   │  写点什么…  ·   按住说话      │
   ╰──────────────────────────────╯
      左侧 1/3       右侧 2/3
```

沿用浅色 #F0F5E9、深色 #102019 场景基底。输入条使用同色系半透明填充与轻微明暗差，不做白色卡片、粗边框或重阴影；实际文字对比度需真机检查。横向留白约 24dp、高约 56dp、圆角约 28dp，底部距安全区约 12dp。两区只用留白或很淡的短分隔表达，不做两个独立按钮。

- 左侧点击：直接聚焦文字输入、弹键盘，整条展开为可编辑文本区，右侧显示发送。1/3 与 2/3 的划分只用于静止态；文字编辑时支持正常选词、粘贴和光标操作。
- 弹键盘时角色保持原大小与位置，内容卡收为摘要，保持首页场景；发送后只更新用户气泡，仍在首页。收起键盘恢复布局，保存未发草稿。
- 右侧短按：不录音、不弹键盘，条上方短暂显示“按住说话，松开发送文字”。
- 右侧长按达到约 300ms：进入录音准备状态；识别器真正就绪后轻震，提示“正在听”，开始显示识别内容。
- 首页是统一输入入口；历史选择“接着聊”也回到该入口，共享草稿，避免两个输入框、重复发送或草稿丢失。

## 5. 黑色语音界面

录音时场景、角色与菜单全部隐去，应用背景和可控制的系统栏切为黑色；系统隐私指示由系统保留。正文为高对比浅色，已确定文字稳定显示，末尾临时识别片段使用稍弱颜色。不要逐字重排整段。

```text
  ┌──────────────────────────────┐
  │                              │
  │   明天下午三点提醒我，       │
  │   把整理好的材料发出去。     │
  │                              │
  │       正在听 · 00:08          │
  │                              │
  │   取消                  编辑 │
  │      ╲                ╱      │
  │        ╲____________╱        │
  │           松开发送           │
  │          手指按住处          │
  └──────────────────────────────┘
```

“取消”和“编辑”位于底部手势圆弧的左上、右上两端，不放在整屏顶端。手指可以从右侧原始按下点向弧两端滑动，目标触区至少 48dp；实际范围随屏幕和安全区适配。文字显示区位于手指上方。

| 手势／事件 | 提示 | 松开后的结果 |
| --- | --- | --- |
| 保持中央发送区域 | 松开发送 | 停止收音，等待最终转写，然后提交一次文本 |
| 滑入左上取消区域 | 松开取消 | 取消本次录音与结果，返回原界面 |
| 滑入右上编辑区域 | 松开编辑 | 停止收音，最终文字进入草稿并弹键盘，手动发送 |
| 从两侧滑回中央 | 松开发送 | 恢复发送意图 |
| 来电、切后台、系统取消触摸 | 录音已中断 | 不自动发送；已有文字保存为草稿 |

进入不同目标时轻震一次，用文案和区域高亮共同指示。触区边缘增加容差，避免抖动在取消和发送之间跳转。抬手时锁定最终意图，后续识别回调不能改变取消或编辑的选择。

重要细节：

- 松开发送的是最终文本，不发送录音气泡。停止收音与最终转写完成是两个状态；等待时显示“正在整理文字…”，不能把半句直接发出去。
- 无人声或最终为空：提示“没听清，再试一次”，不产生空消息。短时间说出的有效词仍可发送，不用时长粗暴过滤。
- 最终转写超时或失败：保留已有片段为可编辑草稿并说明未发送；不静默提交不完整内容。
- 首次权限请求会打断按住动作；授权后回到输入条，让用户重新按住。拒绝权限仍可打字。
- 首版建议单次最多 60 秒；临近上限提示，到上限停止并转编辑，避免意外截断后直接发送。
- 首版选择能返回部分结果和最终结果的流式识别服务，先在实际 Pixel 设备验证中文、标点、时延和网络条件，再确定供应商。系统识别器是否可用不能假设；接口使用可替换的 SpeechInputSession。
- 不要求 ASR 替用户润色，不擅自删改否定词、数字、时间。音频仅用于转写，默认不长期保存；诊断记录不写原始音频。
- 断网后聊天文本保存在待发送状态，明确显示未发送，用户可重试；重试携带同一幂等键。
- TalkBack 提供开始、停止、取消、编辑的可点击替代方式，不能把长按滑动作为唯一入口。

## 6. Harness 分层与数据流

```text
用户文本／首页进入／提醒到期／事项变化
                  ↓
事件入口：事件 ID、来源、时间、时区、会话
                  ↓
上下文：明确记忆、近况摘要、待办、近期展示、用户当前交互状态
                  ↓
规则门控：过期、完成、静默、冷却、去重、打断限制
                  ↓
决策：沉默／首页开场／提醒／继续对话
                  ↓
生成表达或执行受约束工具
                  ↓
持久化消息及投递任务 → 首页／聊天／FCM
                  ↓
展示、阅读、回复、稍后、完成 → 后续决策
```

规则负责是否允许、何时执行、能否调用工具；模型负责相关性排序和自然表达。模型只能从有来源的候选中选择，允许返回 silence。模型生成慢、失败或超时不阻塞首页；明确提醒使用已保存内容照常投递。首页开场生成过程禁止顺带创建提醒或修改记忆。

上下文明确传入当前时间及 IANA 时区。相对时间在用户请求发生时解析，记录原句与解析结果；含糊时间只追问必要信息。明确提醒只有持久化成功才回复“记好了”。时间戳必须带时区，不能把服务器本地时区当成用户时区。

建议拆分：

- App：HomeCoordinator 管首页与开场；ConversationController 管消息、连续发言分组和请求版本；HomeConversationView 管两个最新气泡；ActivityTray 管工具与产物；HistoryActivity 管历史浏览与引用；统一 ComposerView 管文字／语音入口；VoiceOverlay 管手势；SpeechInputSession 管识别；InboxRepository 管同步、去重和回执。
- 服务端：事件与上下文构建、ProactivePolicy、对话与工具执行、ReminderScheduler、DeliveryOutbox。现有 main.py 保留路由入口，逐步拆分，避免一次重写。

建议新增／扩展记录：

- reminder：来源、时区、状态、更新版本、下一次时间、完成时间。
- proactive_event：trigger、source_id、priority、dedupe_key、expires_at、decision_reason。
- message：稳定 ID、source_event_id、conversation_id、group_id、reply_to_message_id、展示渠道、发送状态、created_at、expires_at（投递／候选有效期，不用于删除聊天历史）。
- utterance_group：角色、原始消息 ID 顺序、revision、开始／结束时间、是否结束；用于展示分组及模型轮次编排。
- tool_run / artifact：来源消息组、调用 ID、状态、结果引用、可用操作；与气泡生命周期分离。
- delivery_outbox：message_id、channel、attempt、next_attempt_at、status。
- engagement：设备和会话、displayed_at、read_at、dismissed_at、response_message_id。
- client_outbox：client_message_id、文本、发送状态；同一请求重试不可重复创建提醒等副作用。

建议接口：首页进入评估、分页 inbox 同步、消息回执、提醒完成／延后／修改；现有 chat 扩展 client_message_id 与 reply_to_message_id。首页重复 onResume 使用同一会话键，不重复生成开场。

提醒状态变更、inbox 消息和 outbox 写入放在同一个数据库事务；推送由独立 worker 重试。FCM 只是到达提示，inbox 是可靠记录。通知携带稳定 message_id，前台收到时优先更新界面，后台点击定位同一消息。客户端按 ID 去重，不能依赖推送恰好一次送达。

## 7. 交付顺序

1. 统一消息与草稿：从 ChatPanel 提取发送控制，补稳定消息 ID、失败重试、inbox 同步和通知定位。
2. 首页对话：实现两个独立更新的气泡、连续发言分组、融入场景的输入条、键盘与角色过渡、共享草稿；补首页内容位和历史入口。
3. 语音闭环：黑色覆盖层、流式文字、三个手势目标、最终结果处理与中断恢复。
4. 提醒可靠性：事务 outbox、重试、完成／稍后、到期与过期策略。
5. 主动开场：接入前台事件、上下文候选、频率门控、展示回执与设置。

## 8. 验收场景

- 用户连续发送三段短消息归入一个气泡；Greta 开始新发言后用户再发，替换自己的旧组，不清除 Greta 气泡。
- 任何一方新发言只更新自己的槽位；气泡不会超时消失；重新进入首页恢复最新两组，历史包含全部原始消息。
- 生成中补充时间或取消意图时，旧 revision 不覆盖新回复，工具不重复执行；已执行的动作显示真实结果。
- 工具进度到结果原位更新；新气泡不会清掉进行中任务；多个任务、长内容、窄屏与键盘状态都能找到内容入口。
- 历史定位、分页、引用继续聊与返回均不丢草稿、不改首页最新气泡。
- 连续进出首页十次，同一会话不重复开场；已有到期提醒时不抢先问候。
- 点击输入后才返回的开场候选不会覆盖草稿或打断录音。
- 右侧轻点只提示；长按就绪后显示真实部分转写。
- 中央松开只发送一次最终文字；左上取消后的迟到回调不能发送；右上编辑保留文字且不自动发送。
- 权限拒绝、识别器不可用、无声、断网、来电和切后台均有可恢复状态，无空消息和意外发送。
- 亮／暗主题、窄屏、大字体、键盘与系统手势安全区下，输入和操作可见可达。
- 提醒触发时服务退出、FCM 失败或重复到达，inbox 仍保留唯一记录；通知打开对应上下文。
- 相对日期跨天、时区变更、已完成事项和延后事项不会产生过期误提醒。
- 用户说“少主动找我”，更新主动开场设置；明确的定时提醒按独立设置继续运行。

## 10. 当前实现与验证（2026-10-16）

已接入首页双气泡、原位角色、统一文字入口、语音全黑覆盖层、部分／最终转写、取消／编辑／发送、分页历史、工具结果详情、提醒完成／延后、首页 inbox 同步和通知 ID 定位。普通主动开场由只读上下文生成接口提供，带本地冷却、每日次数及夜间限制；无合适话题可静默。

客户端保留原始发送并映射连续发言组；生成期间补充会排队到下一次请求，旧回复保存在历史但不覆盖当前气泡。首版不会撤销已经开始执行的工具，已完成结果仍如实显示。服务端增加回复缓存、工具操作标识、提醒与 inbox／push outbox 原子写入和推送重试。

语音采用设备安装的系统识别服务，部分结果能力取决于服务；不可用时明确提示并保留文字入口。独立流式服务适配、实时服务端工具事件流、按话题归档与历史引用继续聊尚未接入。当前工具进展显示为处理状态，完成后展示实际工具结果；不能把尚未实现的流式工具进度描述为已完成。
