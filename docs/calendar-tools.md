# 日历、重要日期和大姨妈工具

首版源码实现：2026-10-23。对应视觉稿为 `calendar-agent-tool-design.md` 中已确认的深色星夜／浅色山岚方案。

## 使用入口

首页“••• → 工具 → 日历”。首页没有新增常驻卡片。

- 月历同时显示公历与农历，初一显示月份，支持春节、元宵、端午、七夕、中秋、重阳和腊八名称。
- 应用内月历左滑进入下个月、右滑进入上个月；纵向滑动继续滚动页面，滑动不会误选日期。切月保留选中的日号，目标月没有该日时选月末。
- 顶部女生符号切换大姨妈图层；首次使用进入配置。实际记录、预测、易孕期和预计排卵日分别标记，隐藏后月历、列表、详情一同去除相关展示。
- 点击日期查看当天事项；“日期列表”浏览本月，更多菜单可查看全部重要日期，包括已过去的一次性事件。
- 添加／编辑采用底部抽屉；低频日期规则收进“更多选项”。保存后短暂显示可撤销反馈，普通编辑不额外要求确认。
- 日历是独立全屏工具，编辑使用抽屉；深浅背景、字体及减少动态效果沿用首页设置。
- 编辑抽屉按系统栏和键盘占用的空间限制可见高度；键盘打开后保留表单滚动，输入光标滚动到可见区域。大姨妈设置、实际记录和重要日期共用这一处理。

## 重要日期

支持一次性、每年重复、公历／农历、正数天数、可选第 N 天里程碑、提前提醒、提醒时间与时区、备注及单条删除／撤销。

没有出生年的生日可以只保存月日，内部换算锚点不作为出生年，也不会据此计算年龄。正数和里程碑需要明确起始年份。公历2月29日支持非闰年按2月28日或3月1日；农历支持缺少三十用月末、缺日跳过、闰月缺失采用普通月等明确规则。每次找下一次农历日期时检查同一公历年内的全部候选，处理冬月／腊月同一年出现两次的情况。

日期事实使用手机 SQLite 私有库，与生活记录／Obsidian 导出分离。当前用户可录入的重要日期年份范围为1901—2099。

## 待办与重复

添加菜单可选择“待办”，也可在重要日期表单中切换类型。待办使用完整公历日期，支持不重复、每天、每周、每两周（14天）、每月、每年；首次日期也是重复规则的起点，不会生成起点之前的事项。重要日期也可使用这些重复方式，农历仍支持一次性和每年重复。

每月保持原始日号，短月使用月末，例如1月31日 → 2月28日／29日 → 3月31日。按年重复保留现有闰日规则。待办默认当天09:00提醒，可修改提前天数和时间。

月历、日期列表和桌面近期事项显示待办与完成状态。应用“接下来的日子”和桌面组件按记录ID去重，每件事只显示最近一次未完成的发生日期；不同记录即使同名也分别保留。月历日期标记、某天详情和按月查看仍保留每次发生记录。桌面大月历为事项预留空间，事项区可上下滚动，不再因高度较小或跨月6行而把事项条数降为0。点击桌面待办右侧方框可直接完成当次，手机记录、所有桌面组件和提醒随之更新；点击文字仍打开详情。重复待办完成后移到下次日期，单次待办完成后从近期列表移除，可在日期详情恢复。打开某次待办可标记完成／恢复未完成，只影响该发生日期，后续重复继续；完成和恢复支持撤销。已完成的当次事项不再提醒。过去的单次未完成待办仍在日历中显示逾期；重复待办的历史可按月历日期查看。本版使用按日期固定重复，不按完成日期顺延。

聊天通过 `save_special_date` 的 `event_type=todo` 与 `repeat` 保存，`set_calendar_todo_completed` 按明确ID、版本和发生日期修改完成状态。更新服务端及共享工具定义后，聊天才可使用新增能力；本地表单、重复和提醒不依赖服务端升级。

## 大姨妈

- 实际开始／结束、进行中记录、历史修正、备注。
- 应用和桌面月历共用配色：大姨妈日期为粉底，预计日期增加虚线边；可估算周期内的其他非易孕日期只改为绿字，预计易孕日期为紫字，预计排卵日另绘小花图标。深色用柔和玫瑰粉／浅绿，浅色用淡粉／深绿。缺少预测或周期波动较大时不标绿，不将绿色解释为避孕安全。
- 配置通常周期和持续天数，不能默认为已知28天。
- 初次配置的设置、开始记录和图层状态一并提交、一并撤销。
- 预测为派生数据：最近实际开始加配置周期；记录不足时不自动补事实。
- 可选历史辅助：至少3个完整间隔后使用最近至多6个间隔的中位数，手动周期保留；观测到的波动较大时展示范围，并不显示精确排卵日。
- 首版 `calendar-v1` 算法采用下一次预计开始前14天估算排卵日，并展示前5日至后1日的估算窗口；只是日期启发式，不能验证真实排卵或用于避孕，不输出“安全期”。
- 未填写结束日期不会因通常持续天数到期就自动结束。超过预计到来日期显示尚未记录，不判断已经来、怀孕或疾病。
- 单独控制预测、提醒、AI访问；展示开关只影响展示。

## 本地提醒

重要日期默认提前1天09:00，大姨妈默认提前2天09:00，可修改。默认跟随所在地时间，也能选择固定 IANA 时区。

本机是日历通知的唯一投递端，使用一个可重排的非精确系统闹钟调度下一次提醒／跨日刷新；离线可用，系统省电限制可能延迟。重启、时间／时区变化、安装更新和数据修改会重新计算。修改／删除后撤销过期通知，已提醒的同一发生日期不会因普通备注修改再次响铃。错过提醒时，仅在该日期仍未过去的情况下补发一次。

通知权限或频道被关闭时，工具结果明确说明；用户可从日历更多菜单进入“日历通知设置”。私密通知默认隐藏大姨妈详情，点开进入日历查看。

## 桌面组件

标准 Android RemoteViews 组件不支持横向滑动手势，桌面大月历使用左右箭头切月。不要将应用内的滑动切月能力宣称为桌面组件能力。系统限制见 [Android 组件手势说明](https://developer.android.com/develop/ui/views/appwidgets/overview#gestures)。

系统微件列表提供：

1. 日历 · 大月历：较大尺寸，公历／农历网格、逐日点击、前后月份和近期事项。
2. 日历 · 近期日期：按可用空间显示近期事项，可开启大姨妈预测摘要。
3. 日历 · 单个纪念日：选择一个重要日期，大号显示倒数或已经多少天。

可从日历更多菜单发起系统固定流程，用户确认位置；成功后进入配置。每个实例分别保存主题、专属日期及大姨妈显示，显示开关不改提醒，也不强制同步应用内图层。

大月历优先采用约4×5的较大初始布局，允许拉伸；根据可用高度减少近期事项，保证月历和农历可读。桌面玻璃表面静态，桌面壁纸由启动器管理；应用内保留轻微光点，减少动态效果时停用闪动。数据修改、跨日、系统周期刷新及重启会更新组件。

## Agent 工具

共享 schema：`server/app/client_assets/tools.json`，手机和服务端使用同一份定义。

- 打开／查询：`open_calendar`、`query_calendar`、`get_cycle_summary`。
- 日期：`save_special_date`、`delete_special_date`。
- 大姨妈：`save_cycle_record`、`delete_cycle_record`、`update_cycle_settings`。
- 展示与撤销：`update_calendar_preferences`、`undo_calendar_operation`。
- 桌面：`list_calendar_widgets`、`configure_calendar_widget`，定位已存在组件后配置主题、显示及单个纪念日内容；使用恢复操作ID撤销。新增或移动仍由系统桌面完成。

例句：

- “妈妈农历八月十五生日，每年提前三天提醒我，不记出生年。”
- “离我们的1000天还有多久？”
- “今天大姨妈来了，帮我记一下。”
- “上次其实是10月3日开始的，周期30天，提前两天提醒。”
- “日历里先不显示大姨妈，提醒保留。”
- “把桌面那张单个纪念日卡改成我们的结婚纪念日。”

新增／修改只在明确指令下执行；查询不受原有“必须命令句才能调用本地工具”的限制。更新要求先查精确ID与 revision，不猜目标；每次操作使用稳定 operation_id，重试不重复写入。普通保存／修改／删除均可撤销，后续修改导致版本冲突时要求重新读取。

`query_calendar` 与 `get_cycle_summary` 返回对应范围内的记录、确定性日期结果、配置、版本和相关操作ID，预测与实际分别返回。单次查询至多两年，重要日期结果上限50条并返回截断提示，避免全量内容上传；大姨妈查询最多保留最近50条。实际大姨妈数据关闭AI访问后，服务端或手机直连模型均不能绕过执行器读取、修改或恢复访问。

### 远程工具回传

`POST /v1/chat` 遇到本地日历调用时保留 checkpoint 并返回 `pending_client` 和含 operation_id 的 client_action；手机执行后用 `client_tool_result` 回传，再继续同一轮推理。只有最终答复才进入普通回复缓存。设备身份参与 checkpoint／缓存键，旧结果重发不会错接下一条调用。手机直连 DeepSeek 使用相同执行器和持久会话恢复。

大姨妈读取结果只在相关工具调用时回传给配置的模型；不注入日常主动开场、不写入普通长期记忆或通用导出。含日历健康工具的轮次不进入重要话题自动抽取。成功回复缓存和用户聊天记录仍按既有聊天机制保存用户主动问询与回答，不承诺远程模型或网关不留存其接收的内容。

远程AI闭环需要同步部署修改后的 `server/app/main.py` 和 schema。旧服务端拒绝新增能力时，普通聊天回退旧能力列表；日历请求明确提示需要更新服务端，本地日历和提醒可继续使用。

## 主要文件

- `CalendarActivity.java`：页面和编辑抽屉。
- `CalendarDates.java` / `CalendarMonthView.java`：日期换算与共享月历绘制。
- `CalendarStore.java`：事实、版本、幂等、预测与事务撤销。
- `CalendarUpdates.java`：本地提醒与系统事件刷新。
- `CalendarWidget*.java`：三类组件、配置与Agent配置操作。
- `CalendarTools.java`：固定白名单、参数检查和本地执行器。
- `AssistantApi.java` / `server/app/main.py`：服务端回传闭环及手机直连路径。

## 构建与验收状态

原首版仅进行了开发版构建、服务端 Python 语法检查和差异检查。待办扩展新增独立模拟器回归，覆盖固定间隔、月末、闰日、旧版重复规则、完成／撤销／重试、重复事项查询、提醒日期和表单选项。未安装到真实手机，也没有部署远程服务。本次开发版和测试包构建通过，独立模拟器日历回归14项通过（含真实组件点击完成、三种组件渲染和短尺寸6行月历）；服务端回归沿用此前结果。可用 `adb -s emulator-5556 shell am instrument -w -e suite calendar dev.pixel.sync.dev.test/dev.pixel.sync.ToolUiInstrumentation` 运行新增套件。Pixel 真机的界面、桌面放置、农历重复通知、系统省电条件下的投递、以及真实模型的工具往返仍需实际验收；构建成功不代表这些流程已经跑通。
