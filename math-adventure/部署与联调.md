# 独立数学冒险后端：服务器部署与联调

沿用pixel-app后端的FastAPI、SQLite、独立Bearer凭证、非root容器和Docker Compose方式，在`math-adventure/`内单独构建运行。服务端口默认8788，与pixel-app的8787分开；使用独立命名数据卷，不修改原数据库、服务或Nginx配置。

本轮提供家长页面、10道AI样题草稿、题目版本/检查/人工审核/停用、每日任务、判题、提示与跳过、经验金币流水、设备注册/撤销、心跳和真实API模拟脚本。当前一个已验证邮箱对应一个独立用户，各自拥有正式/试玩角色、题库版本、设备、任务和记录；邮箱验证码登录成功时自动建立账户。旧家长令牌保留为兼容管理入口，不与任意新邮箱自动共享旧数据。

**ESP32已新增v0.3联网固件。** 烧录后通过屏幕上的热点配置Wi-Fi与设备专用令牌，默认地址为`https://ryven.xin/math`。配置步骤见[固件说明](firmware/README.md)；原离线试玩记录不会导入正式学习数据。音频、数字输入、奖励兑换和24周完整课程不在本轮范围。

## 新增：邮箱登录与四位码配对（v0.4）

服务器更新代码后，在现有`math-adventure/.env`追加发信参数，再重新构建容器。邮件密码只存服务器环境，不提交Git，不需要写进ESP32。

```dotenv
MAIL_HOST=smtp.163.com
MAIL_PORT=465
MAIL_SSL_ENABLED=true
MAIL_USERNAME=你的发信邮箱
MAIL_PASSWORD=你的邮箱授权码
MAIL_FROM=你的发信邮箱
MATH_ROOT_PATH=/math
MATH_COOKIE_SECURE=true
```

默认允许任意邮箱完成验证码验证后建立独立用户。如仅限家庭使用，可另设置`MATH_PARENT_EMAILS=邮箱1,邮箱2`限制可登录邮箱。发信账号只承担通知，不会自动获得其他用户权限。验证码6位、5分钟有效、最多尝试5次，发送有冷却与次数限制；登录后采用HttpOnly/Secure/SameSite Cookie保持30天，主动退出会撤销会话。首次登录无需再输入管理员令牌。

配对步骤：

1. 邮箱登录家长网页，选择正式或试玩数据，在设备管理点击“开启四位码配对”。
2. ESP32先通过热点网页**选择Wi-Fi**并输入密码，页面已不需要设备令牌。
3. 屏幕点击“配对设备”或设置中的“开启配对”，用数字键盘输入网页显示的四位码（含前导零），3分钟内有效。
4. 网页出现待确认设备，核对屏幕设备名称与6位校验号，确认绑定。
5. 板子自动获得当前用户数学设备权限并同步任务；不会取得邮箱验证码、网页会话或家长管理权限。配对期间断网/重启可继续轮询恢复，不需要再次手填长令牌。

旧库会自动升级为多用户结构并保留已有设备和学习记录，旧数据留在兼容管理员身份下，不分配给第一个注册邮箱。新邮箱得到独立的10道AI草稿，审核结果不共享。生产环境升级前仍按下文备份数据库。

自动测试使用虚构邮箱和替代发信函数，不发送真实邮件。本机不启动Docker；SMTP实际投递及正式配对在服务器部署后验收。

## 1. 在服务器启动

在服务器拉取本次提交，然后进入仓库目录：

```sh
git pull --ff-only
cd math-adventure
# 首次配置：创建随机家长令牌，不复用INK_TOKEN或其他设备令牌。
# 仅首次执行；已有.env时保留原配置。
python3 tools/init_env.py
docker compose up -d --build
docker compose ps
curl -fsS http://127.0.0.1:8788/health
```

上述初始化脚本只创建一次，已有`.env`时拒绝覆盖；更新服务时只执行`git pull --ff-only`与`docker compose up -d --build`。使用服务器编辑器查看`.env`中的`MATH_ADMIN_TOKEN`，填入家长页面登录。登录时可勾选“记住此设备”，令牌保存在当前浏览器中，后续自动登录；主动退出、清除网站数据或服务端更换令牌后需要重新输入。不勾选时仅当前页面有效。

默认只监听服务器本机127.0.0.1。建议在已有HTTPS站点添加[反向代理示例](nginx.conf.example)，在`math-adventure/.env`中增加：

```dotenv
MATH_ROOT_PATH=/math
```

然后重新执行`docker compose up -d`，检查Nginx配置并重载，在浏览器访问`https://你的域名/math/`；API文档位于`https://你的域名/math/docs`。Nginx示例的末尾斜杠用于去掉`/math/`前缀。已有pixel-app `/gray/`等路由保持原配置。

如果仅通过可信家庭局域网访问，可在`.env`设置`MATH_BIND_ADDRESS=0.0.0.0`，访问`http://服务器局域网IP:8788/`；外网访问使用HTTPS反向代理。可通过`MATH_PORT`更换宿主端口，但容器内端口始终为8788，Nginx上游端口需相应修改。

所有配置见[.env.example](.env.example)。时区默认`Asia/Shanghai`，决定每日任务日期。

## 2. 首次正式使用

1. 登录家长页面，在“题库审核”逐题查看原题、选项、答案、解析、提示和来源。
2. 点击自动检查。检查失败保留草稿；通过后进入待人工审核状态，不会自动发布。
3. 家长独立解题，核对歧义、难度和小屏适配，填写审核人与意见、勾选独立解题确认后发布。生产数据库的10道AI草稿未经本轮人工审核，不视为正式题库。
4. 至少审核好当天要用的题目后，在“今日战报”点击“安排今日任务”。没有足够题目时最多安排3题中的可用数量；无题目时保持空状态，不用草稿填补正式任务。
5. 在设备管理创建“正式”模式设备，保存仅显示一次的设备令牌。设备令牌只能访问绑定玩家的设备API，不能审核或管理题库。
6. ESP32联网固件需配置对应设备令牌后联调。也可先创建“试玩”模式设备，用下面的脚本验证真实后端流程。

首版每日清单一旦生成便固定，同日重启或重新获取不换题。家长查看战报不会提前生成任务，避免审核首题时意外固定一个不完整计划。设备首次获取任务也会自动生成当天清单。

## 3. 模拟设备联调

在家长页面切换到“设备管理”，创建一个**试玩**设备，将返回的令牌放入环境变量。试玩可使用通过自动核验的AI草稿，题目和响应都明确标为practice；不会进入正式玩家的数据或余额。

```sh
# 可在服务器的独立Python环境执行，不必修改容器。
python3 -m venv /tmp/math-device-env
/tmp/math-device-env/bin/pip install httpx==0.28.1
read -rs MATH_DEVICE_TOKEN
export MATH_DEVICE_TOKEN
# 输入试玩设备令牌后按回车。
/tmp/math-device-env/bin/python tools/simulate_device.py --base-url http://127.0.0.1:8788
unset MATH_DEVICE_TOKEN
```

脚本读取当天任务，逐个尝试选项，再复用相同请求ID校验幂等响应。它只接受试玩设备；家长页面选择“独立试玩”即可看到这些真实后端记录、经验和金币。已完成任务不重复新增记录或奖励，重复运行会跳过已完成题。

这里不使用模拟的人工审核，不会把AI草稿发布为正式题目。

## 4. 设备接口契约

所有设备请求使用`Authorization: Bearer <独立设备令牌>`；`/api/math/parent/*`仅接受家长令牌。完整结构与错误响应见服务的`/docs`。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/math/device/state` | 玩家、当天任务与完成状态 |
| GET | `/api/math/adventure/today` | 同上，自动创建或返回当天唯一清单 |
| GET | `/api/math/questions/{id}` | 当前设备当天已分配题目，不泄漏答案 |
| POST | `/api/math/answers` | 服务端判题与事务发奖 |
| POST | `/api/math/tasks/hint` | 获取下一条提示并记录次数 |
| POST | `/api/math/tasks/skip` | 标记稍后再想，不算答对 |
| POST | `/api/math/device/heartbeat` | 更新最后在线时间，返回服务端时间 |

答题JSON：

```json
{
  "task_id": "从当天任务响应获取的ID",
  "answer": 1,
  "duration_seconds": 32,
  "request_id": "设备生成并持久化的唯一请求ID"
}
```

`answer`是选项索引（从0开始），选项最多3个。题目响应不含正确答案、解析或全部提示；正确完成后才返回解析。提示和跳过请求只需`task_id`与`request_id`。

客户端需在发送前持久化请求ID与完整请求内容；网络重试使用完全相同的请求。相同ID与内容返回原始响应（包括当时余额快照），同一ID换内容/操作返回409。重连后重新获取设备状态读取最新余额。跨日后的新提交返回409，但已成功请求的原样重试仍能找回原响应。

正式规则初值沿用需求文档建议：每个逻辑题目首次完成20 XP，首次尝试且未使用提示时5金币，当天全部有效任务解决后额外10 XP，累计100 XP升一级。答错不扣分；同题跨日复习、新版本复习不重复发题目奖励。当天最多3题，因此普通题金币最多15枚。提示和跳过均可幂等重试，稍后再想的题可以回来继续。

修改题目创建新的草稿版本，不改历史答题内容；未审核的新版本不影响旧已发布版本被安排。发布新版本后新计划选择新版本，已有任务保留原版本。停用立即阻止该版本答题并显示不可用，也不会自动退回使用更旧的错误版本。当前未提供当日题目替换，必要时停用后当天题量减少。

## 5. 持久化、备份与更新

SQLite位于命名卷的`/data/math-adventure.db`，事务使用`BEGIN IMMEDIATE`与唯一业务键保护并发发奖。迁移版本1首次启动自动建表、创建正式/试玩玩家，并以幂等方式插入10道草稿；重启不会清空状态或覆盖审核结果。

停容器不会删除数据卷。更新时保持Compose项目目录及项目名一致；如指定`-p`，后续所有命令使用同一项目名。不要使用`docker compose down -v`作为日常更新命令。

在线备份（包含WAL中的最新提交，不直接复制正在写入的数据库文件）：

```sh
docker compose exec -T math-api python -c "import sqlite3; source=sqlite3.connect('/data/math-adventure.db'); target=sqlite3.connect('/data/math-backup.db'); source.backup(target); target.close(); source.close()"
docker compose cp math-api:/data/math-backup.db ./math-backup.db
```

备份包含家庭学习记录，应单独保存。`math-adventure/.gitignore`已排除本地数据库和凭证。

测试覆盖身份隔离、草稿阻止进入正式任务、发布前检查与人工确认、版本与停用、事务幂等、同ID不同载荷冲突、并发提交、提示与跳过、每日奖励、重启恢复、跨日重试以及历史题目不重复发奖。

Docker Compose仅完成静态配置校验，镜像构建及容器启动按本次约定由你在服务器执行。

## 局域网邮箱登录

同时使用 `http://192.168.0.160/math/` 和公网 HTTPS 域名时，将 `.env` 的 `MATH_COOKIE_SECURE` 设置为 `auto`，重新构建并启动数学服务。`auto` 仅允许私有/回环 IP 的 HTTP 页面使用非 Secure 会话 Cookie；公网域名始终使用 Secure，即使后端位于 HTTP 反向代理后。HttpOnly、SameSite 和邮箱账号隔离保持有效。设置 `true` 会要求所有浏览器入口使用 HTTPS，因此 HTTP 局域网页面会在验证码验证后提示“请先登录家长账户”。
